# 流水线实现细节

本文档详细说明 `screen_ocr_pipeline.py` 中每一步的实现原理与调优方法。

## ① ffmpeg 抽帧

**原理**: 使用 ffmpeg 的 `fps` 滤镜按固定频率从视频中均匀抽取帧。

**命令**:
```
ffmpeg -i video.mp4 -vf fps=2 -q:v 2 frames/frame_%05d.png
```

**参数**:
- `fps`: 每秒抽帧数。录屏滚动列表建议 1-3 fps。fps 过高会产生大量相似帧（后续去重会处理），fps 过低可能漏过快速滚动的项。
- `-q:v 2`: 高质量 PNG 输出。

**调优**: 如果录屏中滚动很快，调高 fps（如 3-5）；如果是慢速浏览，1 fps 足够。

## ② 帧去重

**原理**: 对每帧的 ROI 区域转灰度图，缩放至 48×96 计算感知哈希。相邻帧的哈希差异 < `diff_threshold` 时跳过。

**为什么需要去重**: 录屏中用户可能停顿、缓慢滚动或回看，导致大量几乎相同的帧。对这些帧重复 OCR 浪费时间且不增加信息。

**参数**:
- `diff_threshold`: 0.005-0.05。值越低越敏感（保留更多帧），值越高越激进（跳过更多帧）。
  - 录屏静止多 → 调高（如 0.02）
  - 录屏滚动快 → 调低（如 0.008）

**注意**: 去重使用的哈希基于 ROI 区域（如果配置了 ROI），这样只关注数据区域的变化，忽略 UI 其他部分的动画干扰。

## ③ OCR

**原理**: 使用 EasyOCR 对每帧（或 ROI 裁剪后）进行文字识别，返回文本行列表。

**参数**:
- `languages`: OCR 语言。中文录屏用 `["ch_sim", "en"]`。
- `gpu`: 是否使用 GPU。无 GPU 时设为 false。
- `roi`: 裁剪区域。正确的 ROI 能大幅提升 OCR 速度和准确率（排除无关 UI 元素）。

**ROI 调优方法**:
1. 先用 `roi: null`（全图）跑一次 OCR
2. 查看 `ocr_cache.json` 中前几帧的 `text_lines`，确认目标数据在画面中的位置
3. 根据位置设置 `top/bottom/left/right` 裁剪
4. 重新跑，验证提取的候选值数量合理

**断点续跑**: OCR 结果缓存到 `ocr_cache.json`，格式为 `{frame_name: {text_lines: [...]}}`。重跑时已缓存的帧直接跳过。

## ④ 正则提取

**原理**: 对每帧的文本行应用正则表达式，提取匹配的候选值。

**配置**: `extract.patterns` 是一个列表，每个模式有 `name` 和 `regex`。

**示例**:
- 6 位基金代码: `(?<!\d)\d{6}(?!\d)`
- 手机号码: `1[3-9]\d{9}`
- 邮箱: `[\w.+-]+@[\w-]+\.[\w.-]+`

**输出**: 每条提取结果记录 `frame`（帧名）、`frame_idx`（帧序号）、`pattern`（模式名）、`value`（匹配值）、`source_line`（来源文本行），用于后续验证和审计。

## ⑤ 交叉验证

**核心洞察**: 录屏滚动场景中，**真实数据项会在连续多帧中出现**（随滚动逐渐进入/离开视野），而 OCR 误识别通常只在单帧孤立出现。

**三重验证**:

1. **模式过滤** (`false_positive_patterns`): 匹配黑名单正则的值直接丢弃。
   - 全相同数字: `^(\d)\1{5}$`
   - 末尾多个 0: `0{4}$`
   - 连续数字: `^(123456|654321)$`

2. **频率过滤** (`min_detections`): 值必须出现在 ≥ N 帧。
   - 录屏滚动时，一个项通常可见 0.5-2.5 秒，在 2fps 下对应 1-5 帧
   - 设为 2 可过滤大部分单帧误识别

3. **连续性过滤** (`max_gap`): 至少有一对检测帧的间隔 ≤ N。
   - 平滑滚动的项在连续帧中被检测到，间隔通常 1-2
   - 设为 3 可过滤分散在远处帧的偶发误识别

**调优**: 如果结果太少（漏识别），降低 `min_detections` 至 1；如果误识别太多，提高 `min_detections` 或补充 `false_positive_patterns`。

## ⑥ 去噪去重

**原理**: 对通过验证的候选值按值去重（`set`），可选排序。

**输出**: 最终的唯一值列表。

## ⑦ 输出 + 清洗报告

**输出格式**:
- `result.json`: 纯值数组
- `result.ts`: TypeScript 导出，变量名由 `ts_var_name` 配置
- `extracted.json`: 所有正则提取的原始候选（含帧信息）
- `validated.json`: 交叉验证结果（含每个值的通过/过滤状态和原因）
- `cleaning_report.md`: Markdown 清洗报告

**清洗报告内容**（见 `report-schema.md`）:
1. 流水线概览（每步统计）
2. OCR 统计
3. 交叉验证过滤明细（原因分布、检测次数分布、被过滤值样例）
4. 最终结果
5. 配置参数

## 性能优化建议

1. **ROI 裁剪是最大的性能杠杆**: 只 OCR 数据区域，速度可提升 3-10 倍
2. **合理的 fps**: 2 fps 对大多数录屏足够
3. **帧去重**: 避免对静止画面重复 OCR
4. **断点续跑**: OCR 是最慢的步骤，缓存后可随时中断续跑

## 常见问题

**Q: OCR 结果为空？**
A: 检查 ROI 裁剪是否把数据区域裁掉了。先用全图跑一次确认。

**Q: 提取值太少？**
A: 降低 `min_detections`（至 1），或调高 `fps`（抽更多帧）。

**Q: 误识别太多？**
A: 查看清洗报告中被保留的可疑值，补充到 `false_positive_patterns`。

**Q: 某些真实值被过滤了？**
A: 查看 `validated.json` 中该值的 `reason`。如果是 `frequency<N`，说明只在少数帧出现，可能是滚动太快漏了，调高 fps；如果是 `not_consecutive`，说明检测帧分散，可能是多次回看同一位置。
